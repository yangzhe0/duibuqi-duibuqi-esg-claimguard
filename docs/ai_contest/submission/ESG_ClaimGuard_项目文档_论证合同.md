# ESG ClaimGuard 项目文档论证合同

## 核心问题

如何在不牺牲原文可追溯性的前提下，利用大语言模型从长篇 ESG 报告中识别指标披露，并把模型输出转化为复核人员能够核对、处置和留痕的证据任务。

## 一句话论证

针对人工逐页检索成本高、关键词难以覆盖同义表达、自由式大模型问答缺少稳定证据的问题，ESG ClaimGuard 采用“版面解析—候选召回—受约束抽取—确定性证据校验—人工处置”的顺序模型，在 200 份报告形成的 13,000 个指标任务上完成正式运行；现有证据支持系统的工程完整性与证据可追溯性，但不支持未经独立人工评测的准确率主张。

## 子问题与模型映射

| 子问题 | 采用的方法 | 在论证中的作用 | 不采用的方案及原因 |
|---|---|---|---|
| 长篇 PDF 中表格、脚注和跨页内容如何进入统一计算空间 | MinerU 版面解析与页级规范区块 | 给出稳定页码、区块和原文坐标 | 纯文本抽取会丢失版面与表格关系 |
| 如何避免整份报告直接输入模型造成上下文噪声 | ESG-65 指标池与候选召回 | 缩小每个指标的证据搜索空间 | 整份 PDF 单次问答难以控制证据来源 |
| 如何阻止模型在证据不足时补写答案 | 受约束 JSON 与确定性证据合同 | 强制 found 绑定报告、页码、区块和逐字引文 | 仅依赖提示词无法稳定保证可追溯性 |
| 数值如何复算 | value/unit origin 与推导表达式 | 区分原文读取、单位归一和公式推导 | 只保存最终数值无法解释其来源 |
| 模型结果如何进入实际复核 | 问题状态机与工作底稿 | 让人员能够确认、修正、待补材料、接受风险或排除 | 结果表本身不能承载责任与处置记录 |
| 如何证明作品已经完成 | 冻结任务网格、validation、SHA-256、测试与 smoke | 证明数据、流程和软件可复验 | 未经独立人工标注的数据不能用于证明语义准确率 |

## Claim–Evidence 映射

| 主张 | 证据 | 可写到的强度 |
|---|---|---|
| 正式任务全部完成 | 200×65=13,000；唯一键 13,000；error 0 | 可以直接陈述 |
| found 结果可回到解析原文 | 7,688/7,688 通过页码、区块和精确子串合同 | 只能证明内部追溯合同完整 |
| 定量结果保存来源 | 3,214/3,214 具有数值、单位及来源字段 | 可以陈述字段完整，不等于数值语义正确 |
| 单卡顺序运行可执行 | 10,015 次生成调用错误为 0；正式运行记录硬件与墙钟 | 可以陈述该次运行完成，不泛化为所有环境稳定 |
| 系统能支持人工复核 | 工作台具备证据查看、问题处置和底稿导出；API smoke 通过 | 可以陈述功能可运行 |
| 系统准确率领先 | 没有独立人工金标准 | 不得声明 |
| 系统可直接替代审计或鉴证 | 没有法律责任与外部事实验证 | 不得声明 |

## 文章主线

1. 先写复核人员面对的具体任务，不从宏观 ESG 意义起笔。
2. 说明关键词、自由问答和普通 RAG 为什么不能直接形成审阅底稿。
3. 把问题形式化为 `报告 × 指标` 任务及证据有效性约束。
4. 逐步解释解析、召回、抽取、证据门和人工处置为何存在。
5. 用冻结正式运行结果回答“是否跑完、证据能否回原文、软件能否操作”。
6. 明确未回答的问题：语义准确率、企业真实行为、法定合规结论。
7. 结论回到用户任务：减少定位与整理工作，把最终判断留给复核人员。
