# ESG ClaimGuard：赛题与方案定义

## 1. 项目定位

ESG ClaimGuard 面向上市公司可持续发展报告的编制复核人员和内部审阅人员。在报告发布前，系统从长篇 PDF 中提取 ESG 声明与逐字证据，检查数值、单位、主体、期间、范围、总分关系和披露条款，生成可处置、可关闭、可导出的预审问题。

系统不评价企业 ESG 表现，不做排名、投资建议或法定审计。系统的价值是降低人工在数百页报告中定位证据和核对口径的成本。

## 2. 用户任务

```text
上传或选择报告
  → 完成版面和表格解析
  → 提取 ESG-65 声明与证据
  → 生成一致性问题
  → 对照声明、冲突证据和规则依据
  → 确认 / 修正 / 待补材料 / 接受风险 / 排除
  → 导出预审工作底稿
```

用户最终得到的不是一张模型结果表，而是一组带页码、原文、判断依据、处置动作、处理人和版本的工作记录。

## 3. 技术方案

### 3.1 文档感知层

MinerU2.5-Pro-2605-1.2B 使用 `vlm-engine` 解析 OCR、版面、表格、图表、阅读顺序、页码和 bbox。输出被标准化为 canonical page/block 数据，任何后续声明必须能回溯到这里。

### 3.2 声明抽取层

Qwen3.6-27B Q4_K_M 只读取 ESG-65 候选证据，输出固定 JSON。模型负责语义判断；数值、单位、逐字引用、page/block 和 lineage 由确定性程序再次校验。

### 3.3 声明—证据约束图

原子声明表示为：

```text
claim = (subject, metric, period, value, unit, scope, qualifier, evidence)
```

图节点包括声明、证据块、报告实体、期间和规则条款；关系包括 `supports`、`contradicts`、`same_metric`、`part_of`、`derived_from` 和 `governed_by`。

### 3.4 一致性检查

- 同主体、指标、期间和范围下的数值冲突；
- 总量与分项不可复算；
- 比例与分子/分母不一致；
- 值存在但单位缺失或不匹配；
- 声明存在但逐字证据不足；
- 披露条款未找到对应说明，需要人工判断。

系统不把“未找到”直接写成“违规”，也不把未经校准的模型分数解释为错误概率。

## 4. 当前数据规模

- `input_manifest.csv` 冻结选取 200 份 ESG 类 PDF（目录中的其他 PDF 不计入正式队列）；
- 10,528 页；
- ESG-65 指标，E/S/G 为 25/20/20；
- 13,000 个 `report × indicator` 任务；
- MinerU 正式解析已经完成 200/200；
- Qwen 正式抽取已经完成 13,000/13,000，found 7,688、missing 5,312、error 0；
- `validation.json`、`CHECKSUMS.sha256` 和 `COMPLETE.json` 均已生成；产品运行不依赖历史桥接目录。

## 5. 评价框架

工程完成指标：

- 报告、页数和结果网格完整性；
- 推理成功率和失败恢复；
- evidence quote 可追溯率；
- quantitative 字段完整率；
- 单页、单报告、单调用时延；
- 峰值显存和内存；
- lineage 与校验和完整性。

若另行开展独立准确率研究，其指标必须来自与生产结果隔离的人工金标准：

- 披露发现 Precision / Recall / F1；
- 字段级匹配；
- 证据页和最小证据集合指标；
- supported / contradicted / insufficient Macro-F1；
- 校准与 risk-coverage。

独立人工准确率评测不属于本次参赛交付范围。因此，本作品最终只报告已经完成并可复验的工程指标、证据追溯结果和人工处置能力，不声明 Precision、Recall 或 F1。

## 6. 创新点

1. 专用文档视觉模型与单一强推理模型顺序运行，避免两套大模型同时驻留。
2. ESG-65 候选约束减少长文档无关上下文。
3. 模型输出必须通过逐字证据和 page/block lineage 门禁。
4. 声明—证据约束图将抽取结果转为数值、语义和条款问题。
5. issue-level 人工处置形成可关闭问题和可导出工作底稿。
6. 全链路保留 PDF hash、parsed hash、模型、prompt、指标池、run_id 和 result_id。

## 7. 交付标准

最终交付以 200/200、13,000 条、error=0、validation 全通过的冻结正式数据为底座；网站、论文、项目文档、视频和 ZIP 全部由该底座生成。冻结输出路径中的版本字符只用于保持运行证据，不代表另有可用的旧产品或运行时依赖。
